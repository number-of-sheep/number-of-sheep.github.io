오늘 새 글을 추가한 뒤 `bundle exec jekyll serve`가 갑자기 실패하는 현상을 겪었습니다. 처음에는 새 글의 Markdown 문법 오류나 front matter 문제를 의심했지만, 실제 원인은 로컬 Ruby/Bundler 환경에서 gem을 찾지 못한 문제였습니다.

### 에러 메시지

제가 실행했던 명령어는 아래와 같습니다.

```bash
bundle exec jekyll serve
```

여기서 발생한 에러의 핵심 메시지는 다음과 같습니다.

```text
Could not find jekyll-4.4.1, json-2.13.2, rouge-4.6.0, sass-embedded-1.89.2, rexml-3.4.1, google-protobuf-4.31.1, bigdecimal-3.2.2 in locally installed gems
Run `bundle install` to install missing gems.
```

이 메시지는 "Markdown 문법 오류"가 아니라, Bundler가 Gemfile.lock에 적힌 패키지를 현재 실행 환경에서 찾지 못한다는 뜻입니다.

### 실제 원인

프로젝트에는 `Gemfile`과 `Gemfile.lock`이 정상적으로 존재했고, lockfile에도 필요한 버전들이 명시되어 있었습니다. 더불어 이전에도 계속 Github Page를 잘 쓰고 있었는데, 수정한 파일이라고는 새 Markdown 포스트 하나뿐이었습니다.

그렇다면 원인은

1. 현재 터미널 환경에 gem이 아직 설치되지 않음
2. gem을 설치한 환경과 실행한 환경이 다름 (예: WSL/PowerShell/CMD 혼용)

중 하나로 의심해볼 수 있습니다. 추가로 아래 메시지도 확인되었습니다.

```text
Bundler 2.6.3 is running, but your lockfile was generated with 2.7.1.
Installing Bundler 2.7.1 and restarting using that version.
```

이건 lockfile 생성 시점의 Bundler 버전과 현재 버전이 달라서, Bundler가 맞는 버전(2.7.1)을 설치 후 재시작했다는 의미입니다.

확인해 보니 이전까지 제가 WSL/Ubuntu에서 작업하다가, 이번에는 PowerShell에서 작업을 했습니다. 이로 인해 WSL과 PowerShell 간에 gem 설치 경로가 달라져서 발생한 문제로 보입니다.

### 해결 과정

생각보다 해결 방법은 간단했습니다. 그냥 아래 명령어를 실행해서 필요한 gem들을 다시 설치해주면 됩니다.

```bash
bundle install
```

설치 후에는 정상적으로 서버가 실행되었습니다.

```text
Server address: http://127.0.0.1:4000/
Server running... press ctrl-c to stop.
```

### 마무리

글만 수정해도 아래 상황이면 같은 문제가 생길 수 있습니다.

1. 터미널 세션이 바뀌면서 Ruby 경로/환경이 바뀐 경우
2. 시스템 업데이트 또는 셸 전환으로 gem 경로가 달라진 경우
3. 이전에 설치된 gem 캐시가 정리된 경우

따라서

1. 가능하면 같은 셸(예: 항상 PowerShell 또는 항상 WSL)만 사용하기
2. 실행 전 문제가 있으면 먼저 아래를 고정 루틴으로 실행하기

    ```bash
    bundle install
    bundle exec jekyll serve
    ```

요약하자면, 이번 실패 원인은 새 Markdown 포스트가 아니라, Bundler가 lockfile에 맞는 gem을 현재 환경에서 찾지 못한 것이었습니다.

---

### Gemfile.lock

이번 troubleshooting 과정에서 `Gemfile.lock`도 일부 변경되었습니다. 제가 의도적으로 버전을 수동 수정한 것은 아니고, `bundle install`을 PowerShell(Windows Ruby) 환경에서 실행하면서 Bundler가 현재 플랫폼에 필요한 항목을 lockfile에 자동 반영한 것입니다.

추가된 핵심 내용은 아래와 같습니다.

1. `PLATFORMS`에 `x64-mingw-ucrt`가 추가됨
2. `ffi`에 `1.17.2-x64-mingw-ucrt` 변형이 추가됨
3. `google-protobuf`에 `4.31.1-x64-mingw-ucrt` 변형이 추가됨
4. `sass-embedded`에 `1.89.2-x64-mingw-ucrt` 변형이 추가됨

왜 바뀌었는지 요약하면, lockfile은 "모든 환경에서 동일한 의존성 그래프"를 유지하되 각 플랫폼별 바이너리 gem 정보도 같이 저장합니다. 이전에는 Linux/Unix 계열 플랫폼 위주 정보가 들어 있었고, 이번에 Windows 환경에서 install을 수행하면서 Windows용 항목이 추가된 것입니다.

즉 이 변경은 오류가 아니라, 서로 다른 개발 환경(WSL과 PowerShell)을 오갈 때 흔히 생기는 정상적인 lockfile 업데이트입니다.
